The bot overhaul PLAN

Every bot gets three parts: perception (what it can honestly see and hear), a mind (Jev choosing goals every second or on an event) and motor (code running at 60 Hz: moving, aiming, dodging, bank shots). Jev chooses what to do and code carries it out. When nobody human is playing, a free code mind runs the city instead, so it stays alive around the clock.

Jev decides judgment

  • Which goal to pursue now (a closed list; code only offers goals valid in this assignment)
  • Which visible rat to aim at, or none
  • Where to go for each goal (open-ended goals only: flee, ambush, roam, mischief)
  • How much danger the rat is in
  • Whether a bank shot is the way to reach the target

Code decides exact

  • What the rat can see and hear, and the candidate lists Jev picks from
  • Places a goal implies: the case, the carrier, the medkit, the zone, the delivery
  • Routes, jumps, launchers, stairs and the sewer
  • Aim, lead, bank angles and fire timing
  • Checking that answers are still true: the target is alive and the world hasn't changed
  • Personality weights, skill dials, budget, fallback

04The cast: 80 / 10 / 10

All three share the same Jev answers. A personality is just weights that code applies to the probabilities, so it adds no calls and no cost. Skill is separate: the same dials apply to aim and reaction whatever the personality. Personalities are hidden from players; they work it out from behaviour.

Limits that shape it

  • Price: $0.042 per million input tokens; output free. About 1,700 tokens per decision with the per-goal place questions.
  • Requests: 1,200 per minute, on Rat Detective's own TypeSafe account. One room deciding every second uses 540, so two busy rooms fit. Beyond that: decide less often, or ask TypeSafe for a higher limit.
  • Budget guard: $25 a day in production, as a Worker variable. When it's reached, rooms fall back to the code mind until the next day.
  • Key: Worker secret TYPESAFE_API_KEY, on staging first. Model pinned to jev-1.13.0.

07Failure modes, written first

Each one gets its guard before the code it guards. The deterministic ones get a failing test first.

What could go wrongGuard
Jev is slow, down or rate-limitedRat keeps its last goal; the code mind answers after 600 ms; exponential backoff on 429
An answer arrives after the world changedSerial and age check (≤ 1.5 s); target must still be alive and in view; otherwise dropped
Parallel questions disagree (goal: case, place: alley)One place question per goal; code uses the place the goal implies
Rats flip-flop between goalsHysteresis: switch only when the new goal wins by a margin or an event fires
Every bot does the same thingCast weights plus sampling from the probabilities instead of always taking the top answer
A player names themselves to steer the botsRats are sent as r1..r9; chosen names never reach Jev
Bots get too goodSkill lives in the motor: reaction delay, aim error, fire cap. Their hit rate stays under the human median on the map
Bots cheat with knowledge a human lacksPerception gives what a human gets: sight, the Hunch, sounds, the HUD's case marker
Cost runs awayJev only with humans; daily cap; per-room cadence; tokens logged per decision
The game stallsExecutors always move forward; the 30 s and 90 s rescues stay; the case recovery stays

08How we'll know it works

Baseline (no soaks)

Today's bots are already recorded on layout 3 in production. The /map digest gives their numbers before any change: time per place, deaths, fire and hit rates, banked-hit share, stuck anomalies.

Decision facts

Every decision is recorded: mind (Jev or code), goal and its top probabilities, confidence, latency, tokens, dropped as stale or not, and whether the goal was achieved.

Bots against humans

Per place: do bots go where humans go and die where humans die? Tryhards should look like humans; the target is humanlike, not optimal.

The repeatable artifact at the end: a receipt with the baseline digest, the new digest, the decision stats (goal mix per personality, latency p50 and p90, dollars per hour, fallback share) and the side-by-side maps.

10How the bots keep getting better

Every game played teaches the bots something. Each decision is recorded with what happened next, so we can see which choices worked and which didn't. Then we change something, test the change against thousands of real recorded moments, ship it as a new version and measure again. The loop never stops, and it gets faster as the data grows.

1 · Every game is data

Every decision fact carries its outcome, so after a week of play we can answer questions like "do Tryhards who chase the carrier through the precinct yard die more often than ones who wait at the lineup-room stairs?" The answers are the evidence for the next change.

2 · The test set grows by itself

Recorded moments become the exam. Before a change ships, the new question wording or weights are replayed against them, and good calls that stop being made show up before any player sees them. More play makes a bigger exam.

3 · The free bots inherit it

The code mind that runs the empty city can copy what Jev chose in recorded situations. As the Jev bots get smarter, the $0 living city gets smarter too, without calling Jev.

"Better" means more fun, not stronger

Success is measured on the humans: longer sessions, more rounds, players who come back, fights spread around the city. The bots aim to play like people, including the 10% who just want chaos. Base bots never outplay Tyler; a nightmare tier would be a separate dial.

One change at a time

Like layoutVersion for the city, every decision carries a mindVersion, and each version changes one thing. So every improvement (or mistake) shows up cleanly in the data and can be undone. An agent can run most of the loop; Tyler decides what ships.

What doesn't change: Jev's own weights. TypeSafe doesn't retrain Jev on customer data; you shape it through what you send it. So the tuning happens in everything around the model: the questions, the situation text, the weights and the code. That's also what keeps every step measurable and reversible.
